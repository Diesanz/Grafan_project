\section{¿Qué es Grafana?} \cite{grafana_ausum} \cite{grafana_video}

\textbf{Grafana} es un software de código abierto que permite consultar, visualizar, alertar y comprender datos en tiempo real sin importar dónde estén almacenados mostrados a través de paneles elegantes y flexibles.\\

Las principales \textbf{características} de Grafana son:

\begin{itemize}
    \item Permite crear \textbf{dashboards} altamente interactivos con gráficos y tablas que se pueden personalizar y explirar en tiempo real.
    \item Admite una amplia variedad de fuentes de datos como \textbf{bases de datos} \textit{SQL} y \textit{NoSQL}, sistemas de \textbf{monitoreo} como \textit{Prometheus} y \textit{Graphite} y sistemas en la \textbf{nube} como \textit{AWS CloudWatch} y \textit{Google Stackdriver}.
    \item Ofrece una amplia gama de opciones de \textbf{visualización} como gráficos de líneas, barras, dispersión, termómetros y más.
    \item Aporta la posibilidad de crear \textbf{alertas} basadas en umbrales y condiciones definidas por los usuario capaces de notificar a través de correo electrónico u otros canales de comunicación.
    \item Facilita la \textbf{exploración} y \textbf{análisis} de datos mediante funciones de búsqueda, filtrado y agregación, que permite a los usuarios investigar tendencias y patrones en los datos.
    \item Altamente seguro con sistemas basados en autenticación de usuarios y controles de acceso a datos basados en roles.
\end{itemize}

Según estas características algunos \textbf{casos de uso} son los siguientes:

\begin{enumerate}
    \item \textbf{Monitoreo} de infraestructura: supervisar el rendimiento de servidores, redes y bases de datos, identificando problemas y optimizando recursos.
    \item \textbf{Visualización} de métricas de aplicaciones: rastrea el rendimiento, identifica cuellos de botella y mejora la experiencia del usuario.
    \item \textbf{Análisis} de registros: correlacionar datos de registros con métricas para investigar problemas y tendencias en sistemas distribuidos.
    \item \textbf{Observabilidad} de microservicios: monitorizar la salud y rendimiento de estos para identificar problemas de comunicación entre servicios.
    \item \textbf{Seguridad} informática: visualizar datos de seguridad, como registros de acceso, eventos de autenticación y actividad sospechosa, para detectar y responder a las amenazas de manera más eficiente.
\end{enumerate}

\section{Base de datos}

\textbf{Grafana} necesita estar conectada a una base de datos para poder crear sus tablas y esquemas para mostrar los valores que se almacenan en ellas. Utilizaremos MySQL, en donde Grafana puede utilizarlo de dos maneras distintas:

\begin{itemize}
    \item Como base de datos interna de Grafana, para usuarios y permisos, dashboards y paneles o ajustes o auditorías.
    \item Como fuente de datos externa, en donde Grafana realizará consultas SQL a los datos y creará gráficos para mostrarlos, construyendo así dashboards dinámicos.
\end{itemize}

En nuestra práctica hemos conectado una base de datos MySQL llamada ''grafana'' con URL host ''localhost:3306'' debido a que 3306 es el puerto predeterminado de MySQL.

        \item Este comando crea un nuevo usuario llamado 'grafanareader' que solo puede conectarse desde el mismo servidor ('localhost') y le asigna la contraseña 'Grupo6esi'.

    \item \textbf{Creación de la base de datos 'grafana':}
    \begin{itemize}
        \item Ejecutar el comando: \lstinline{CREATE DATABASE grafana;}
        \item Este comando crea una nueva base de datos llamada 'grafana'.
    \end{itemize}

    \item \textbf{Selección de la base de datos 'grafana':}
    \begin{itemize}
        \item Ejecutar el comando: \lstinline{USE grafana;}
        \item Este comando selecciona la base de datos 'grafana' para que todas las operaciones posteriores se realicen en ella.
    \end{itemize}

    \item \textbf{Ejecución del script SQL para crear las tablas:}
    \begin{itemize}
        \item Ejecutar el comando: \lstinline{source /home/usuario/esi/db/tablasGrafana.sql;}
        \item Este comando ejecuta el archivo SQL especificado, que contiene las instrucciones para crear las tablas necesarias en la base de datos 'grafana'.
        \item Es importante que el archivo \texttt{tablasGrafana.sql} exista en la ruta especificada.
    \end{itemize}

    \item \textbf{Otorgar privilegios al usuario 'grafanareader':}
    \begin{itemize}

        \item Este comando otorga al usuario 'grafanareader' permisos totales sobre todas las tablas de la base de datos, ya que se va a querer leer y insertar datos con este usuario.

    \begin{itemize}
        \item Ejecutar el comando: \lstinline{FLUSH PRIVILEGES;}
        \item Este comando recarga los privilegios de MySQL para que los cambios surtan efecto inmediatamente.
    \end{itemize}

\subsection{Conexión a la base de datos}\label{subsec:conexión-db}
Este código define una conexión con la base de datos \textbf{MySQL} en Ubuntu. El script está desarrollado en Python y maneja tanto la conexión con la base de datos como su cierre.\\

\begin{lstlisting}[language=python]
def get_connection():
    try:
        """
        Establece una conexión con la base de datos MariaDB utilizando los parámetros proporcionados.
                
        return: Devuelve un objeto de tipo conexión a la base de datos si la conexión es exitosa.
                Si ocurre un error, devuelve None.
        """
        connection = pymysql.connect(
            host= "localhost",
            port= int(3306),
            database= "grafana",
            user= "grafanareader",
            password= "Grupo6esi",
            charset='utf8mb4',  # Evita problemas de encoding
            cursorclass=pymysql.cursors.DictCursor
        )
        return connection
    except pymysql.MySQLError as e:
        print("Error al conectarse a la base de datos:" + str(e))
        return None
\end{lstlisting}

\vspace{0.4cm}
Explicación:

\begin{itemize}
    \item \textbf{get\_connection()}: Establece una conexión con la base de datos MySQL. Para ello, se deben especificar el \textit{host, puerto, nombre de la base de datos, usuario y contraseña}. Retorna un objeto de conexión \textbf{pymysql.connections.Connection} si la conexión es exitosa; en caso contrario, retorna \textbf{None}.
    \item \textbf{close\_connection()}: Cierra una conexión existente con la base de datos. Requiere como parámetro un objeto de conexión \textbf{pymysql.connections.Connection} que será cerrado.
\end{itemize}

\subsection{Script de creación de tablas}

Lo primero que se puede ver en el script es el comando \lstinline{DROP TABLE IF EXISTS}, que tiene como objetivo asegurarse de que no existan tablas previas con los mismos nombres antes de crear unas nuevas. Especialmente tiene estas ventajas:

\begin{itemize}
    \item Evitar errores por duplicación.
    \item Facilitar la ejecución repetida.
    \item Asegurar un entorno limpio.
    \item Evitar dependencias inválidas.
\end{itemize}

El siguiente comando distinto es \lstinline{DROP PROCEDURE IF EXISTS}, que tiene una función similar a \lstinline{DROP TABLE}, pero aplicada a procedimientos almacenados.\\

Las tablas de la base de datos tiene en común que su \textbf{clave primaria} es el 'timestamp', que es una marca de tiempo que representa un momento específico. Debido a que no puede haber dos momentos de tiempo es un atributo ideal para ser la clave primaria de cada tabla.\\

Más allá de la clave primaria, en cada tabla se recogen distintos \textbf{tipos} de datos según lo que se quiere recopilar, como datos de tipo INT, FLOAT, VARCHAR(255), que todos estos tienen la peculiaridad de que no pueden ser un valor nulo.\\

Además, en este script se define el procedimiento 'AddDatos', cuya declaración es la siguiente:\\

\begin{lstlisting}[language=sql]
CREATE PROCEDURE `AddDatos` (
    IN `carga_cpu` FLOAT,
    IN `frecuencia_cpu` FLOAT,
    IN `mem_ram` FLOAT,
    IN `mem_swap` FLOAT,
    IN `espacio_disco` FLOAT,
    IN `io_operaciones` INT,
    IN `num_proc` INT,
    IN `bytes_env` INT,
    IN `bytes_rec` INT,
    IN `conexiones` INT,
    IN `paq_env` INT,
    IN `paq_rec` INT,
    IN `d` INT,
    IN `h` INT,
    IN `m` INT,
    IN `s` INT,
    IN `carga_sis_1` FLOAT,
    IN `carga_sis_5` FLOAT,
    IN `carga_sis_15` FLOAT,
    IN `nucleos_log` INT
)
\end{lstlisting}

\vspace{0.4cm}
El procedimiento acepta varios \textbf{parámetros de entrada} (IN) que representan los datos de rendimiento del servidor (excepto los valores correspondientes a las tablas interfaces y procesos).\\

Una vez recibidos estos parámetros, 'AddDatos' calcula la marca de tiempo actual que registrará en qué momento se han recopilado los datos. Además, define un controlador de errores que se activa si ocurre alguna excepción SQL durante la ejecución del procedimiento.\\

Posteriormente, comienza una \textbf{transacción} para asegurar que todas las operaciones de inserción se realicen con éxito o se reviertan en caso de error.\\

Comenzada la transacción, el procedimiento introduce los datos que ha recibido como parámetros en las tablas correspondientes (excepto en las tablas interfaces y procesos). También, antes de introducir los nuevos datos, borra los datos de las tablas  \textbf{CPU, Disco, Num\_procesos, Tiempo\_activo y Sistema} que estaban registrados anteriormente.\\

Finalmente, si todas las operaciones se realizan con éxito, se confirma la transacción (COMMIT), guardando los cambios en la base de datos.

\section{Servicio de Ubuntu}\label{sec:servicio-ubuntu}
Este código define un servicio de \textbf{systemd} de Ubuntu, que ejecuta un script desarrollado en python3 dedicado a la recolección de datos del servidor y enviarlos a Grafana. El servicio depende de MySQL y se reinicia automáticamente si falla.
Este código se encuentra dentro de \textbf{/etc/systemd/system/} con el nombre de \textbf{programa-grupo6.service}.
\\

\begin{lstlisting}[language=bash]
[Unit]
Description=Daemon programa esi
After=network.target
After=mysql.service
Requires=mysql.service

[Service]
ExecStart=/usr/bin/python3 /home/usuario/esi/script/script_grafana.py
WorkingDirectory=/home/usuario/esi
Restart=always
User=usuario
Group=usuario

[Install]
WantedBy=multi-user.target 
\end{lstlisting}

\vspace{0.4cm}
Explicación:

\begin{itemize}
    \item \textbf{[Unit]} $ \rightarrow $ define la descripción y dependencias del servicio. Indica que se ejecuta después de que la red y MySQL estén activos.
    \item \textbf{[Service]} $ \rightarrow $ especifica el comando para iniciar el script, su directorio de trabajo y que se reiniciará en caso de fallo. Además, se ejecutará con el usuario \textit{usuario}.
    \item \textbf{[Install]} $ \rightarrow $ indica que el servicio debe ejecutarse en el nivel \textit{multi-user.target}.
\end{itemize}

\section{Explicación del código} \cite{programacionpython80889555} \cite{psutil}
En esta sección se explica el código correspondiente al script \textbf{script\_grafana.py}, que es el encargado de recolectar los datos y almacenarlos en la base de datos.
\subsection{Bucle while del servicio}\label{subsec:bucle-while}

\begin{lstlisting}[language=python]
# Configuración de conexión a la base de datos
conn = None

try:
    conn = get_connection()  # Obtener la conexión a la base de datos

    if conn:
        print("Conexión a la base de datos establecida correctamente")
        # Obtener el tiempo que el servidor ha estado activo
        boot_time = psutil.boot_time()  # Tiempo de arranque, momento en el que arrancó el servidor

        # Ejecuta la recolección e inserción de datos en intervalos regulares
        while True:
            data = collect_data(boot_time)  # Llama a la función collect_data para recolectar los datos
            if data:
                insert_data(data, conn)  # Llama a la función insert_data para insertar los datos en la base de datos

            time.sleep(5)  # Espera 5 segundos antes de la siguiente medición
except Error as e:
    print("Error al conectar con la base de datos:" + str(e))
finally:
    if conn:  # Si la conexión fue exitosa, se cierra
        close_connection(conn)  # Cierra la conexión al finalizar el programa
\end{lstlisting}

\vspace{0.4cm}
Explicación:

\begin{itemize}
    \item \textbf{Establecimiento de conexión}: Se establece la conexión con la base de datos mediante el método \textbf{get-connection()}.
    \item \textbf{Comprobación de conexión}: Se verifica si la conexión fue exitosa.
    \item \textbf{Bucle while}: Este es un bucle infinito que estará activo mientras el servicio siga en ejecución. Dentro de este bucle:
    \begin{itemize}
        \item Se recopilan datos utilizando el método \textbf{collect-data()}, que se explica más adelante en la sección~\ref{subsec:recolección-datos}.
        \item Se insertan los datos recogidos en la base de datos con el método \textbf{insert\_data()}, que se explica más adelante en la sección ~\ref{subsec:almacenamiento-datos}.
        \item Se espera 5 segundos antes de repetir el proceso.
    \end{itemize}
    \item \textbf{Manejo de errores}: Captura posibles errores de conexión con la base de datos.
    \item \textbf{Cierre de conexión}: Se cierra la conexión, si existe, dentro del bloque \texttt{finally} para evitar posibles fugas de recursos mediante el método \textbf{close\_connection(conn)}.
\end{itemize}

\subsection{Recolección de datos}\label{subsec:recolección-datos}

Para la recolección de datos se ha utilizado una librería de Python llamada \textbf{psutil}, que se encarga de obtener información de los procesos y utilización del sistema como puede ser la cpu, memoria, discos, redes o sensores y que funciona tanto en Windows, MacOS o Linux.\\

A continuación se hará un listado de las métricas recogidas con la librería psutil:

\begin{enumerate}
    \item Carga instantánea de CPU $ \rightarrow $ \lstinline{psutil.cpu_percent(interval=1)}
    \item Frecuencia intantánea de CPU $ \rightarrow $ \lstinline{psutil.cpu_freq().current}
    \item Uso de memoria RAM y memoria SWAP $ \rightarrow $ \lstinline{psutil.virtual_memory().percent} y \lstinline{swap_memory().percent}
    \item Espacio en disco $ \rightarrow $ \lstinline{psutil.disk_usage('/').percent}
    \item Operaciones de E/S $ \rightarrow $ \lstinline{psutil.disk_io_counters().read_count}
    \item Número de bytes enviados y recibidos  $ \rightarrow $ \lstinline{psutil.net_io_counters().packets_sent} y \lstinline{psutil.net_io_counters().packets_recv}
    \item Número de paquetes enviados y recibidos  $ \rightarrow $ \lstinline{psutil.net_io_counters().bytes_sent} y \lstinline{psutil.net_io_counters().bytes_recv}
    \item Número de conexiones de red activas si las hubiera  $ \rightarrow $ \lstinline{len(psutil.net_connections(kind='inet'))}
    \item Información detallada de los procesos en ejecución  $ \rightarrow $ para ello se creó una clase que recopilaba todos los detalles de los procesos:
    \begin{lstlisting}[language=python]

    for nombre_interfaz, interface_addreses in psutil.net_if_addrs().items():
            direccion_mac = None

\subsection{Almacenamiento de datos}\label{subsec:almacenamiento-datos}
Para el almacenamiento de datos se ha utilizado la función \textbf{insert\_data}, que se encarga de insertar los datos en las tablas una vez han sido recogidos. El código de esta función es el siguiente:
\begin{lstlisting}[language=python]
def insert_data(data: DatosSistema, conn):
    
    if conn:
        try:
            cursor = conn.cursor()

            # Inicia una transacción
            conn.begin()

            # Eliminar procesos anteriores
            cursor.execute("DELETE FROM procesos;")

            # Insertar los detalles de los procesos
            #Esto se realiza debido a que hay que insertar varios procesos en la tabla
            cursor.executemany("""INSERT INTO procesos (pid, cpu_percent, memory_percent, vsz, rss, usuario, nombre, ruta, hilos, estado)
                                VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s)""", data.to_tuple_proc_info())  # `data.to_tuple_proc_info()` devuelve los detalles de los procesos

            # Borrar los detalles anteriores de las interfaces
            cursor.execute("DELETE FROM interfaces;")

            # Insertar los detalles de las interfaces de red.
            cursor.executemany("""INSERT INTO interfaces (nombre, direccion, mascara, mac, broadcast, bytes_enviados, bytes_recibidos)
                               VALUES (%s, %s, %s, %s, %s, %s, %s)""", data.to_tuple_interfaces_detail())

            # Llamar al procedimiento almacenado para insertar los otros datos del sistema
            cursor.callproc("AddDatos", data.to_tuple())  # `data.to_tuple()` devuelve los otros datos en formato adecuado para el procedimiento

            # Confirmar la transacción
            conn.commit()

            cursor.close()
            print("Datos insertados correctamente en la BD.")
        except Error as e:
            conn.rollback()  # Si ocurre un error, revertir la transacción
            print(f"Error al insertar datos: {e}")
\end{lstlisting}
Explicación:
\begin{itemize}
    \item \textbf{insert\_data()} recibe por parámetros lo siguiente:
    \begin{itemize}
    \item \textbf{data}: Un objeto `DatosSistema` que contiene los datos recolectados del sistema. DatosSistema se define en la clase \textbf{datos\_sistema.py}, cuya cabecera es la siguiente:  
    \begin{lstlisting}[language=python]
    class DatosSistema:
        def __init__(self, carga_cpu, frecuencia_cpu, mem_ram, mem_swap,
                     espacio_disco, io_operaciones, proc_detail, num_proc,
                     bytes_env, bytes_rec, conexiones, paq_env, paq_rec, dias, horas, minutos, segundos,interfaces_detail,
                     carga_sis_1, carga_sis_5, carga_sis_15, nucleos_log):
    \end{lstlisting}
    \item \textbf{conn}: Conexión a la base de datos MySQL.
    \end{itemize}
    \item Esta función sigue los siguientes pasos:
    \begin{enumerate}
        \item Verifica si la conexión a la base de datos `\textbf{conn}` está activa.
        \item Inicia una transacción con `\textbf{conn.begin()}`.
        \item Elimina los datos antiguos de la tabla `Procesos` y los reemplaza con los nuevos datos obtenidos de `\textbf{data.to\_tuple\_proc\_info()}`. Este método devuelve una \textbf{lista de tuplas}, donde cada tupla contiene los detalles de un proceso, resultando más fácil la inserción de estos datos en la base de datos.
        \item Borra los registros previos de la tabla `Interfaces` y los actualiza con `\textbf{data.to\_tuple\_interfaces\_detail()}`. Al igual que el método anterior, devuelve una \textbf{lista de tuplas}, donde cada tupla contiene los detalles de una interfaz.
        \item Llama al procedimiento almacenado \textbf{`AddDatos`} para insertar el resto de datos del sistema sistema.
        \item Confirma la transacción con `\textbf{conn.commit()}`. Si hay algún error, revierte la transacción con `\textbf{conn.rollback()}`.
    \end{enumerate}
\end{itemize}
\section{Métricas de Rendimiento Adicionales}

En adición a las medidas de rendimiento obligatorias, se han seleccionado las siguientes medidas adicionales para obtener una visión más completa del funcionamiento del sistema:

\subsection{Hilos por Proceso y Número Total de Hilos}

\textbf{Utilidad:}
\begin{itemize}
    \item Permite comprender la carga de trabajo a nivel de hilos, identificando cuellos de botella y problemas de concurrencia.
    \item El número total de hilos en uso proporciona una visión general de la utilización de la CPU y la memoria.
    \item Ayuda a diagnosticar problemas de rendimiento relacionados con la sobrecarga de hilos o la falta de paralelismo.
    \item Se puede verificar si el sistema está utilizando de forma óptima los recursos disponibles.
\end{itemize}

\subsection{Estado de los Procesos (idle, running, sleeping)}

\textbf{Utilidad:}
\begin{itemize}
    \item Ofrece una visión clara de la actividad de los procesos y la utilización de la CPU.
    \item Permite identificar procesos que consumen demasiada CPU (running) o que están inactivos (idle) durante períodos prolongados.
    \item Ayuda a detectar problemas de bloqueo o espera (sleeping) que pueden afectar el rendimiento.
    \item Se puede verificar si el sistema está realizando las tareas de forma adecuada.
\end{itemize}

\subsection{Paquetes Enviados y Recibidos}

\textbf{Utilidad:}
\begin{itemize}
    \item Proporciona información sobre el tráfico de red del sistema.
    \item Permite identificar problemas de congestión de red o pérdida de paquetes.
    \item Ayuda a diagnosticar problemas de rendimiento relacionados con la comunicación de red.
    \item Es muy útil para verificar el funcionamiento de los servicios de red.
\end{itemize}

\subsection{Tiempo de Actividad del Sistema (uptime)}

\textbf{Utilidad:}
\begin{itemize}
    \item Indica la estabilidad y disponibilidad del sistema.
    \item Permite identificar reinicios inesperados o fallos del sistema.
    \item Es útil para evaluar la fiabilidad del sistema a lo largo del tiempo.
    \item Es una medida básica pero muy útil para verificar la estabilidad de un sistema.
\end{itemize}

\subsection{Interfaces de Red (IP, MAC, broadcast, bytes enviados y recibidos)}

\textbf{Utilidad:}
\begin{itemize}
    \item Proporciona información detallada sobre la configuración y el tráfico de red de cada interfaz.
    \item Permite identificar problemas de configuración de red o cuellos de botella en interfaces específicas.
    \item Ayuda a diagnosticar problemas de rendimiento relacionados con la comunicación de red a nivel de interfaz.
    \item Permite verificar si el sistema está utilizando las interfaces de red de forma adecuada, y si está habiendo un uso excesivo de alguna de ellas.
\end{itemize}
\subsection{Carga del Sistema}


La carga del sistema mide el número promedio de procesos en ejecución o en espera de ejecución en un momento dado.

\textbf{Utilidad:}
\begin{itemize}
    \item Indica la carga general del sistema.
    \item Permite identificar momentos de alta carga que pueden afectar el rendimiento.
    \item Ayuda a diagnosticar problemas de sobrecarga o cuellos de botella en la CPU.
    \item En sistemas con múltiples núcleos, se puede comparar la carga con el número de núcleos para evaluar la utilización.
    \item Permite verificar si el sistema está realizando las tareas de forma adecuada.
\end{itemize}
Además, hemos optado por recoger la carga del sistema de 1, 5 y 15 minutos. De esta forma pordemos identificar patrones y tendencias en la carga del sistema.
Por ejemplo, si el valor de 1 minuto es más alto que los valores de 5 y 15 minutos, puede indicar un pico de carga puntual.
Por el contrario, si los 3 valores son elevados, inidcaría que el sistema está sobrecargado de forma constante o durante un periodo de tiempo prolongado.

\subsection{Interfaces de red}

La información de las interfaces de red se muestra en Grafana en un panel de tipo ''Table'', permitiendo visualizar y filtrar claramente toda la información recopilada de las distintas interfaces de red.\\

La consulta SQL que se ha utilizado es:

\begin{lstlisting}[language=SQL]
SELECT nombre as Nombre, direccion as Dirección, mascara as Máscara, mac as Mac FROM grafana.interfaces 
\end{lstlisting}

\vspace{0.4cm}
Esta consulta muestra la siguiente información de las interfaces de red:

\begin{itemize}
    \item Nombre: es el nombre que se asigna a una interfaz de red.
    \item Dirección IP: es el identificador único asignado a una interfaz de red dentro de una red.
    \item Máscara de red: determina qué parte de la dirección IP identifica a la red y qué parte identifica el host.
    \item Dirección MAC: es el identificador físico de la tarjeta de red.
    \item BytesEnviados: es el número de bytes enviados por la interfaz.
    \item BytesRecibidos: es el número de bytes recibido por la interfaz.
\end{itemize}

\subsection{Carga del sistema}

La carga del sistema se muestra en Grafana mediante un panel de tipo \textit{Gauge}, ya que este tipo de panel es ideal para visualizar el valor instantáneo de la carga, acompañado de una semicircunferencia que indica su estado.\\

Dado que nuestro sistema cuenta con dos núcleos, el valor máximo representado en la semicircunferencia es 2. La interpretación de la carga es la siguiente:

\begin{itemize}
    \item \textbf{Carga normal (verde):} Entre 0 y 1.4 (hasta el 70\% de la capacidad total).
    \item \textbf{Carga media (amarillo):} Entre 1.4 y 2.
    \item \textbf{Carga alta (rojo):} Igual o superior a 2.
\end{itemize}

La consulta SQL que se ha utilizado es:

\begin{lstlisting}[language=SQL]
SELECT carga1 as 1minuto, carga5 as 5minutos, carga15 as 15minutos FROM grafana.sistema
\end{lstlisting}

\vspace{0.4cm}
Esta consulta muestra el valor inmediato de la carga del sistema en 1, 5 y 15 minutos.

\section{Conclusión}
En este proyecto, hemos desarrollado un servicio de monitorización de servidores utilizando \texttt{psutil}, MySQL y Grafana. A través de la implementación de diversas métricas y la creación de visualizaciones personalizadas, hemos logrado obtener una visión detallada del rendimiento y estado del servidor.

\begin{itemize}
    \item La recolección de métricas permite identificar posibles cuellos de botella y optimizar el rendimiento del servidor.
    \item La integración con MySQL ha facilitado el almacenamiento y la consulta de datos.
    \item Con Grafana se ha podio demostrado lo facil que sería crear una serie de tablas para la visualización de datos, permitiendo la creación de paneles personalizados.
\end{itemize}

En resumen, este proyecto ha demostrado la viabilidad y utilidad de utilizar \texttt{psutil}, MySQL y Grafana para la monitorización de servidores.
